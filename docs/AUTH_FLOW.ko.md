# Microsoft 인증

영문 버전: [AUTH_FLOW.md](AUTH_FLOW.md)

플레이어는 자신의 Microsoft 계정으로 로그인합니다. 런처는 비밀번호를 다루지 않으며, 토큰은
런처 설정 폴더 안의 OS 보호 MSAL 캐시에 저장됩니다.

## 최초 1회 설정 (런처 빌드당)

`LauncherConfig.MicrosoftClientId`는 비어 있는 상태로 배포되고, 내장된 기본 ID를 가진
라이브러리도 없습니다. 따라서 운영자가 앱을 등록하고 이 값을 채우기 전까지 로그인은
비활성화되며, 런처는 설정 안내를 표시합니다.

1. **Azure Portal → Microsoft Entra ID → 앱 등록 → 새 등록.**
2. **지원되는 계정 유형: 개인 Microsoft 계정.** 라이브러리가 authority를 `consumers` 테넌트로
   고정하므로, 조직 전용("디렉터리")으로 등록하면 마인크래프트 계정 로그인이 절대 되지 않습니다
   (`unauthorized_client: not enabled for consumers` 오류).
3. **인증 → 플랫폼 추가 → 모바일 및 데스크톱 애플리케이션 → 리디렉션 URI `http://localhost`.**
   반드시 이 플랫폼이어야 하며 "웹"이 아닙니다. 공용 클라이언트로 등록해야 런타임에 브라우저가
   고르는 임의의 loopback 포트와 매칭됩니다. "웹"으로 등록하면 매번
   `invalid_request: The provided value for the input parameter 'redirect_uri' is not valid`
   오류가 납니다.
4. **인증 → 고급 설정 → 공용 클라이언트 흐름 허용: 예.** 디바이스 코드 폴백에 필요합니다.
5. **애플리케이션(클라이언트) ID**를 `LauncherConfig.MicrosoftClientId`에 붙여넣습니다.
6. **그 클라이언트 ID에 대해 마인크래프트 API 사용 승인을 신청**합니다:
   <https://aka.ms/mce-reviewappid>.

클라이언트 ID는 비밀값이 아니라서 커밋해도 됩니다. **하나의 등록으로 모든 런처 빌드와 모든
플레이어를 커버**합니다. 서버마다 앱을 따로 만들지 마세요 — 6번 승인이 클라이언트 ID 단위라
새로 만들면 다시 받아야 합니다.

## 마인크래프트 API 승인 (6번 상세)

클라이언트 ID가 승인되기 전까지는 Microsoft 로그인·Xbox Live·XSTS가 모두 통과하고, 마지막
`login_with_xbox` 호출만 **403**을 반환합니다. 런처 버그로 오해하기 쉽지만 아닙니다. 런처는
이를 "마인크래프트 계정 확인을 거부했습니다(403)"로 표시합니다.

폼은 애플리케이션 ID, 디렉터리(테넌트) ID, 관련 웹사이트, 사유를 요구합니다. 제출하려면
**실제 로그인 시도가 최소 한 번 선행**되어야 하므로, 신청 전에 보이는 403은 정상이며 이것이
Microsoft 쪽에 앱을 등록시키는 역할을 합니다.

**승인은 메일로 통지되지 않습니다.** 확인 메시지가 없고, 어느 순간 로그인이 그냥 되기
시작합니다. 승인 후 반영까지 최대 약 24시간이 걸립니다. 확인 방법은 메일을 기다리는 게 아니라
**로그인을 다시 시도**하는 것입니다.

## 로그인 방식

런처는 **시스템 브라우저**로 로그인하고 loopback 리디렉션을 직접 받습니다. 브라우저를 아예
띄울 수 없는 환경(헤드리스, SSH, 최소 데스크톱)에서는 **디바이스 코드 방식**으로 폴백해
코드와 주소를 창에 표시합니다. 로그인 취소는 사용자의 결정으로 간주하며, 조용히 디바이스
코드로 다시 시작하지 않습니다.

시작 시 `TryRestoreAsync`가 캐시된 세션을 재사용합니다. 이는 best effort라, 캐시된 계정이
없거나 리프레시 토큰이 만료됐거나 네트워크가 없으면 그냥 로그인 버튼이 표시될 뿐 시작 오류가
되지 않습니다.

MSAL 캐시와 마인크래프트 계정 파일은 `LauncherConfig.LauncherId` 기준으로 분리되므로, 서로
다른 서버 빌드가 자격 증명을 공유하지 않습니다.
